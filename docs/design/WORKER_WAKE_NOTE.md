# A worker window's last wake (design only)

The Bridge can observe only its own window's wakes. A last-wake note would report that observation, not prove that a worker read a task or acted. This note proposes a separate informational metadata family; it adds no route, storage, lane field or Bridge behavior in this slice.

A future authenticated worker route would replace one bounded record for the credential's own actor/window, with an operation identity, a server observation time, an optional bounded client time, a closed reason code and a bounded pointer to the triggering task when visible. It would accept neither another actor nor free-form instructions. Per-actor/window limits, rate limits, expiry and bounded storage must be decided before implementation. Server time controls age and retention; client time is untrusted display data. Retries of the same operation must not advance the observation time. Out-of-order observations must not overwrite a newer one. A revoked credential or lost project grant must refuse both a new write and a replay.

Coordinators could read these notes only for actors in projects they currently coordinate; the writer could read its own. Task pointers require current project/task visibility. Cross-project metadata, hidden identifiers and counts must not leak through shared actors. The display would label the note as a worker-window report, and distinguish absent, stale and unreadable from never-woken. Multiple windows must not be collapsed into an assertion that the whole lane was woken.

The storage must be separate from comments and semantic checkpoints/lane state. The current checkpoint route rejects unknown fields; adding an ad hoc field there would silently alter its contract. Do not repurpose waiting_on, not_before, last activity or empty-wake records.

The coordinator view and wait response could include the metadata as an informational annotation only. It must not enter any fingerprint, whose-move decision, activity cursor, comment pointer, trigger list, trigger count, quiet-lane age, timer or queue ordering. Updating, expiring or removing it alone must never wake anyone, including its writer. Readers must not write observations merely because they displayed one. Before implementation, tests must pin existing fingerprints byte for byte with and without notes, across retries, expiry, permission loss and many windows; an update-only integration test must show both worker and coordinator waits remain asleep. No native task history write and no unbounded read or periodic scan is justified by this feature.

A server-held worker wait is separate work. A held request uses an HTTP handler thread, socket and connection slot even while no lock or backend connection is held. Its admission budget must be shared with coordinator waits and reserve ordinary-route headroom; a wake note must not bypass or enlarge that budget.
